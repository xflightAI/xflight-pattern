# M4-B2 — Geometry Membership and Direction Evidence

`GeometryMovementEvidence.Evaluate(configuration, snapshot, minimumUsableGroundSpeedMetresPerSecond)` is a stateless Core operation. It uses the M3 threshold-derived runway frame and the M4-B1 policy and envelopes. The caller supplies a finite, positive minimum usable speed; no speed threshold is inferred from the aircraft or M3 geometry. Evaluation does not inspect prior samples or return a confirmed phase.

An available position is projected through `RunwayGeometryReference.ToRunway`. An unavailable position gives null runway position and false membership for every region. Membership is closed at boundaries. Entry, Crosswind, Downwind, and Final use their M3 oriented rectangular corridors. Departure/Upwind is the union of the M3 runway centerline corridor (with M3 half-width) and the M3 Upwind corridor. The Base region uses the M3 BaseArea. Its along-track limits remain exactly the Base Turn Window interval `[-Bf, -Bn]`; policy margins only enlarge its cross-track bounds. `InsideBaseTurnWindow` reports the unexpanded M3 window separately and never confirms a Base turn. Runway contact and outer exit use the unexpanded M4-B1 closed envelopes. A false `InsideOuterExitEnvelope` with null `Position` means the position is unavailable, not known to be outside. Even with a valid outside position, false membership alone must never be interpreted as a confirmed exit; persistence and phase decisions belong to a later detector.

Leg enter and exit bounds expand their flat ends and sides by the respective explicit corridor margins. The larger exit margin permits spatial hysteresis in a later detector. A position may be in more than one region; each region's enter and exit result remains independent. In particular, Base may overlap Final and Downwind. The evaluator does not choose a winner or produce a candidate, transition, cue, or persistence count.

True ground track is interpreted as clockwise degrees from true north. Each leg's start-to-end travel vector is rotated from runway coordinates into east/north using the M3 threshold-derived forward and right vectors. Its true bearing is compared with the observed true ground track using the shortest circular difference in degrees. Base compares with travel from the selected side toward the runway centerline. Departure/Upwind compares with runway-forward travel. Errors at or below the enter tolerance have `WithinEnterTolerance`; errors only within the exit tolerance have `WithinExitTolerance`; larger errors have `OutsideExitTolerance`. The comparison admits at most the next representable `double` degree value above each configured tolerance to cover a one-ULP upward rounding of the final angular subtraction. It adds no fixed-degree epsilon; a track farther outside remains outside. These direction results are independent of current position and region membership.

Direction is unavailable when ground speed is unavailable, below the caller's minimum usable speed, or true ground track is unavailable. The status names identify the reason, and angular error is null. An exact-speed threshold qualifies. M4-B1 validates available numeric telemetry (including track range and finiteness), so invalid available track cannot enter this evaluator through a valid `TelemetrySnapshot`. Altitude, vertical speed, and on-ground observations are not used for this horizontal evidence.
